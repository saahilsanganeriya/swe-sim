# Part A — grader and stakeholder review

The grader correctly rejects inconsistent ordinary pytest evidence, protects the listed control files, and gives zero reward for regressions. It does **not** establish that mutually consistent evidence was produced by genuine test execution: submitted Python shares pytest's process and owns its result files. That limitation is acknowledged in the docs. The current stakeholder changes improve disclosure, but do not fully enforce the reporter boundary: unsafe information can survive in requirements, several visible fields bypass sanitization, and the API deliberately exposes the patience tier. I would not treat the current combination as a strict reward/disclosure boundary.

This report is independent of Part B. ## Findings, ranked

**A-P1-1 — Consistent in-process falsification is not handled (acknowledged residual).** The result directory is chowned to `tester`; that process receives the JUnit destination and `SWESIM_NODEIDS`, loads the submitted roots, and executes pytest. The parent checks consistency only after it exits. A submitted import, repository plugin, or exit handler can therefore affect the very engine and evidence being trusted. Reading only the last terminal summary cannot authenticate its author. Established by code reading, not by executing a falsifying submission: [swesim/verifier/grader.py:317](/private/tmp/swesim-independent-review/snapshot/swesim/verifier/grader.py:317), [swesim/verifier/grader.py:369](/private/tmp/swesim-independent-review/snapshot/swesim/verifier/grader.py:369), [swesim/verifier/run_pytest.py:12](/private/tmp/swesim-independent-review/snapshot/swesim/verifier/run_pytest.py:12), [swesim/verifier/run_pytest.py:25](/private/tmp/swesim-independent-review/snapshot/swesim/verifier/run_pytest.py:25), [swesim/verifier/parsers.py:65](/private/tmp/swesim-independent-review/snapshot/swesim/verifier/parsers.py:65). The existing captured-output test establishes a narrower defense: [tests/test_grader.py:156](/private/tmp/swesim-independent-review/snapshot/tests/test_grader.py:156). Consequence: a coherent false pass can receive credit. Smallest honest improvement: add a control for this residual and qualify claims about forged summaries; actually closing it requires keeping the assertion engine and authoritative observations outside the submitted Python process. Another parser check is not a complete fix. The docs explicitly acknowledge this at [docs/grading.md:121](/private/tmp/swesim-independent-review/snapshot/docs/grading.md:121).

**A-P1-2 — Demoting a fact does not remove its disclosure through requirements.** `ledger_violations(..., demote_unsafe=True)` marks an unsafe fact author-only and clears its test links, but merely sets a linked requirement's `fact_id` to `None`; its text remains. Every requirement text then enters the stakeholder view and prompt. The runtime deny-list exempts identifiers present in those requirements. Thus a requirement repeating a hidden identifier can both put it in context and exempt it from redaction. Moreover, the draft sanitizer only checks discovery `on-request` and `brief`, while `repo-derivable` and `volunteered-at-review` are also visible. Established by [swesim/stages/draft_spec.py:441](/private/tmp/swesim-independent-review/snapshot/swesim/stages/draft_spec.py:441), [swesim/stages/draft_spec.py:1283](/private/tmp/swesim-independent-review/snapshot/swesim/stages/draft_spec.py:1283), [swesim/stakeholder/view.py:28](/private/tmp/swesim-independent-review/snapshot/swesim/stakeholder/view.py:28), [swesim/stakeholder/view.py:40](/private/tmp/swesim-independent-review/snapshot/swesim/stakeholder/view.py:40), and [swesim/stakeholder/prompts.py:62](/private/tmp/swesim-independent-review/snapshot/swesim/stakeholder/prompts.py:62). The test explicitly verifies that the link is cleared, but uses harmless requirement text `"r"`, so it misses the disclosure: [tests/test_swebench_source.py:1270](/private/tmp/swesim-independent-review/snapshot/tests/test_swebench_source.py:1270). Consequence: the fact label's exclusion is sound but the information boundary is not. Smallest fix: validate every stakeholder-visible field, remove or regenerate requirements depending on demoted facts, and derive permitted vocabulary from validated reporter evidence before whitelisting it.

**A-P1-3 — A2's worker-only patience-tier rule is contradicted by the API.** `Reply.public()` returns `patience_remaining` and `tier`; the service returns that dictionary directly. This is explicit, tested behavior, not an inferred leak: [swesim/stakeholder/session.py:118](/private/tmp/swesim-independent-review/snapshot/swesim/stakeholder/session.py:118), [swesim/stakeholder/service.py:207](/private/tmp/swesim-independent-review/snapshot/swesim/stakeholder/service.py:207), [tests/test_service.py:51](/private/tmp/swesim-independent-review/snapshot/tests/test_service.py:51). Consequence: an agent making the HTTP request can read the internal tier. The ordinary shim displaying only reply text would not change that API boundary. Smallest fix, if A2 is the intended contract: omit `tier` from public responses and adjust the test; retain only whatever availability signal the contract expressly permits. **Documentation distinction:** [docs/architecture.md:86](/private/tmp/swesim-independent-review/snapshot/docs/architecture.md:86) actually says remaining patience and tier are public. The code matches that paragraph, but not the review's A2.7 requirement.

**A-P1-4 — The general reporter stance remains partly prompt-enforced.** The output filter recognizes a finite identifier list and only letter options `(a)`–`(e)` / `option a`–`option e` present in the current request. It cannot reject an ordinary answer such as “use the first approach,” unlisted implementation advice, or arbitrary verification advice as a class. `confirm` accepts any nonempty string within its size limit, including code; it is a channel convention, not a check that the input describes behavior. Established by [swesim/stakeholder/session.py:45](/private/tmp/swesim-independent-review/snapshot/swesim/stakeholder/session.py:45), [swesim/stakeholder/session.py:175](/private/tmp/swesim-independent-review/snapshot/swesim/stakeholder/session.py:175), [swesim/stakeholder/session.py:233](/private/tmp/swesim-independent-review/snapshot/swesim/stakeholder/session.py:233); the marker-based test is [tests/test_session.py:295](/private/tmp/swesim-independent-review/snapshot/tests/test_session.py:295). Consequence: “does not choose implementations” and “never sees code” are stronger than the implementation. Smallest useful change: qualify these as prompt rules, restrict confirmation input to a structured behavioral description, and extend adjudication/filter tests beyond literal option letters. Full semantic enforcement is not supplied by a larger word list. There are no v2 trial replies on disk with which to measure residual frequency.

**A-P3-1 — Timeout and forged-output prose overstates the narrower checks.** The docs say diagnostic reruns use the remaining budget, but `_diagnostic_reruns` starts a fresh `test_timeout_sec` deadline after the initial invocation. This is still bounded: compilation deliberately budgets 600 seconds per invocation and 1,800 seconds for the verifier. The worked example “forges summary lines → outcome 4” is only true when the forgery disagrees with the other evidence. Established by [docs/grading.md:63](/private/tmp/swesim-independent-review/snapshot/docs/grading.md:63), [docs/grading.md:108](/private/tmp/swesim-independent-review/snapshot/docs/grading.md:108), [swesim/verifier/grader.py:393](/private/tmp/swesim-independent-review/snapshot/swesim/verifier/grader.py:393), [swesim/stages/compile.py:34](/private/tmp/swesim-independent-review/snapshot/swesim/stages/compile.py:34). Smallest fix: document the separate diagnostic budget and qualify the forged-output example. I found no resulting positive reward from a timeout.
